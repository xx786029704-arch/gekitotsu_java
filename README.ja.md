**Flashゲーム『激突要塞』の統合ツールボックス**

[English](README.md) | [简体中文](README.zh-CN.md) | 日本語

激突Kit は、『激突要塞』の物理エンジンを忠実に再現した上で構築されたファンメイドのツールボックスです。一括対戦シミュレーション、エフェクトプラグイン対応の陣形ワークベンチ、貢献分析、軌道予測、ユニット図鑑、リンク集などを提供し、陣形の研究・検証・最適化を行いたい上級者・ハードコアプレイヤーを対象としています。

> 本プロジェクトは非公式のファン作品です。原作および原作者とは一切関係がなく、承認も受けていません。

## 機能一覧

| モジュール | 説明 |
|-----------|------|
| **対戦シミュレーション** | 1P と 2P の陣形リストの全対戦をマルチスレッドで実行し、勝率統計を出力します。 |
| **貢献分析** | プレイヤーの陣形から n 個の兵玉を削除した組み合わせを列挙・サンプリングして一括対戦し、勝率変化や軍資金あたりの変化でランキングします。 |
| **陣形ワークベンチ** | 陣形コードのデコード・編集・プレビュー・再エンコード、ユニットと要塞の情報表示、内蔵アナライザー、ワークフロー型エフェクトプラグイン。 |
| **軌道予測** | ズーム・パン可能なキャンバス上で要塞の移動や突撃の軌道を可視化します。式とユーザー定義変数に対応。 |
| **ユニット図鑑** | 全 63 ユニット（id 0–62）のスプライト、ステータス、説明、戦術、最速行動計算を閲覧できます。 |
| **リンク集** | 原作公式サイトや日中コミュニティのリソースにワンクリックでアクセスできます。 |

- GUI：Java Swing + FlatLaf 3.5.4。ダーク／ライトテーマとアクセントカラーのカスタマイズに対応。
- シミュレーションエンジン：外部依存ゼロ、純粋な `java.awt` 幾何計算により Flash 原作を 1 フレーム単位で再現。
- UI 言語：簡体字中国語。

## ダウンロードと実行

### Windows パッケージ（推奨）

1. Releases ページから最新の `激突Kit vX.Y.Z.zip` をダウンロードします。
2. 任意の場所に解凍します。
3. `激突Kit/激突Kit.exe` を実行します。JRE 21 ランタイムが同梱されているため、Java のインストールは不要です。

本アプリは作業ディレクトリの `1P.txt`、`2P.txt`、`config.ini` を読み込み、`result.txt` と `simple_result.txt` を出力します。`config.ini` は初回起動時に自動生成されます。

### ソースから実行

必要な環境：JDK 21+（Maven は任意）。

```bash
# Maven で実行可能な fat JAR をビルド
mvn package

# GUI（デフォルト）
java -jar target/gekitotsu_java-1.8.0.jar

# CLI
java -jar target/gekitotsu_java-1.8.0.jar --cli
```

ランタイム同梱の Windows 実行ファイルをビルドするには、プロジェクトルートで `build_exe.bat` を実行します。事前にスクリプト冒頭の `JDK_HOME` と `M2` のパスを環境に合わせて変更してください。出力は `dist/` に生成されます：

- `dist/激突Kit/激突Kit.exe` — JRE 同梱のアプリケーションイメージ（アイコン埋め込み）
- `dist/激突Kit v1.8.0.zip` — リリース用アーカイブ

## コマンドラインモード

```bash
java -jar target/gekitotsu_java-1.8.0.jar --cli
```

CLI は `1P.txt` と `2P.txt`（1 行につき 1 陣形、`名前&コード` 形式）を読み込み、対話式メニューを表示します：

| 項目 | 動作 |
|------|------|
| `0` | 全対戦を開始し、`result.txt` / `simple_result.txt` を出力 |
| `1` | 1 試合あたりのフレーム上限を設定 |
| `2` | HP スコア記録のオン／オフを切り替え |
| `3` | 陣形ファイルを再読み込み |
| `4` | スレッド数を設定 |
| `9` | 終了 |

## 機能ガイド

### 1. 対戦シミュレーション

1P と 2P の陣形リストの全組み合わせを実行し、勝率統計を出力します。

1. **陣形の編集** — 「1P阵容」「2P阵容」タブに陣形コードを貼り付けます。編集内容は 500ms のデバウンス後に `1P.txt` と `2P.txt` へ自動保存されます。
2. **パラメータ設定**：
   - **フレーム上限** — 1 試合あたりの最大シミュレーションフレーム数（デフォルト 65536）。
   - **スレッド数** — 並列シミュレーションのスレッド数（デフォルトは CPU コア数）。
   - **HP スコア** — 結果に残り HP と HP スコアを表示します。
   - **折り返し** — 結果テキストを自動折り返しします。
3. **開始** — 「开始模拟」をクリックすると、プログレスバーとステータス行に進捗と経過時間が表示されます。
4. **結果の確認** — 「详细结果」「简要结果」タブに `result.txt` と `simple_result.txt` の内容が表示されます。

### 2. 貢献分析

各兵玉が陣形の勝率にどれだけ貢献しているかを定量化します。削除後の勝率低下が大きいほど重要な兵玉です。

1. **入力**：
   - **元の陣形** — 分析対象のプレイヤー陣形。`1P.txt` からインポートできます。
   - **評価用陣形セット** — 評価基準となる相手陣形の集合。`1P.txt` / `2P.txt` からインポートするか、クリアできます。
2. **パラメータ**：
   - **探索率** — 削除組み合わせをランダムサンプリングする割合（100% で全列挙）。
   - **削除数 n** — 1 組み合わせあたりに削除するユニット数。
   - **スレッド数** — ワーカースレッド数。
   - パラメータ横のラベルにシミュレーション対象の組み合わせ数が表示されます。組み合わせ数が 1,000,000 を超える場合は開始できません。
3. **開始／停止** — まずベースライン勝率を計算し、その後スライディングウィンドウ方式で結果を逐次返し、残り時間の目安を表示します。いつでも停止できます。
4. **結果**：
   - **ユニット集計** — ユニットごとの平均勝率変化と平均軍資金あたり変化。
   - **組み合わせランキング** — 勝率変化または軍資金あたり変化で並べた削除組み合わせ（列ヘッダーのクリックで並べ替え）。n = 1 の場合はユニット集計のみ表示されます。
   - 行を選択して「复制」をクリック（またはダブルクリック）すると、該当ユニットを削除した陣形コードをコピーできます。

### 3. 軌道予測

要塞の移動と突撃の軌道を可視化し、弾道や突撃の仕組みの研究を支援します。

- **リスト（左側）** — 軌道・要塞壁・変数の 3 つのタブ：
  - 軌道は手動追加のほか、陣形コードからの自動インポートに対応。
  - 変数 `a`–`z` は軌道の式から参照できます。
  - クリックで選択、ダブルクリックで編集、ドラッグで並べ替え、Shift/Ctrl+クリックで複数選択、カラースウォッチのクリックで色を変更。
- **キャンバス（右側）** — マウスホイールでカーソル位置を基準にズーム（0.1x–5.0x）、左ボタンのドラッグでパン。現在のズーム倍率は右下に表示されます。
- **ショートカット** — `Delete` 削除、`Ctrl+C` コピー、`Ctrl+V` 貼り付け、`Ctrl+X` 切り取り、`Ctrl+A` 全選択、`Ctrl+D` 選択解除。選択項目は人間が読めるテキスト形式でコピーされ、リスト間で貼り付けられます。
- **軌道パラメータ** — 名前、突撃壁 x、兵玉 x/y、1P/2P 加速レベル、突撃段数、近距離／遠距離突撃壁、兵玉コード順序、色。座標には変数を含む整数式を使用できます。

### 4. 陣形ワークベンチ

陣形制作の中心となるツールです。左に input/output、中央にプレビュー、右に情報とワークフローを配置した 3 カラム構成です。

#### 編集と解析

- **入力欄** — 陣形コードを貼り付けると、デコード結果のプレビューがリアルタイム更新されます。
- **出力欄** — 再エンコードされた陣形コードを表示します。
- **➡ ボタン** — 出力欄の内容を入力欄へコピーし、反復編集を容易にします。
- **中央プレビュー** — 陣形をレイヤー描画します（要塞壁が背面、兵玉が前面）。背景をクリックすると背景色を変更できます。

#### ユニット・要塞情報

- プレビュー下部に選択中ユニットの詳細（名前、HP、CD、AT、cost、座標）を表示します。「单位列表」でユニット項目をクリックすると選択を切り替えられます。
- 「要塞信息」には現在の陣形名、加速レベル、総軍資金などの概要が表示されます。

#### 内蔵アナライザー

ワークベンチは以下の問題を自動検出し、修正案を提示します：

- **重なり検出** — 同種の兵玉が近すぎる、または完全に重なっている。
- **突撃最速検出** — 突撃壁内の兵玉が着地最速の x 座標を採用しているか。
- **壁玉座標の提案** — 壁玉の x 座標が推奨位置（54 / 114 / 174 / 234 / 294）にあるか。
- **槍玉の角度検出** — y = 349 の槍玉の角度を 2 に変更すべきか。
- **愈玉／繕玉の位置検出** — 愈玉・繕玉がユニットリスト内で後ろすぎないか。

#### ワークフローとエフェクトプラグイン

右カラムでは、一連のエフェクトをワークフローとして現在の陣形に適用できます。

- **エフェクトライブラリ** — 検索ボックスで絞り込み、ダブルクリックまたはドラッグでワークフローパネルに追加します。
- **ノード操作** — クリックで有効／無効を切り替え（●/×）、ダブルクリックでパラメータ編集、右クリックでメニュー、長押しドラッグで並べ替え、選択して `Delete` で削除。
- **エラー表示** — 実行に失敗したノードは赤い枠と ⚠ アイコンで表示され、ホバーするとエラーメッセージを確認できます。

#### カスタムエフェクトの開発

エフェクトプラグインの JAR は `effects/` ディレクトリに配置します。`.java` ファイルを `effects/build_plugin.bat` にドロップすると、自動的にコンパイルされてプラグイン JAR にパッケージされます（JDK 21+ が必要）。`effects/samples/CopyAndRenameEffect.java` は 4 種類のパラメータ型（`INT` / `STRING` / `BOOLEAN` / `UNIT_ID`）と `validate` / `execute` インターフェースを網羅した完全なサンプルです。詳細は `effects/samples/README.md` を参照してください。

### 5. ユニット図鑑

全 63 ユニット（id 0–62）を閲覧できます：

- **左側のリスト** — 項目をクリックすると詳細を表示します。
- **右側の詳細** — スプライト（100×100）、名前、コード、折り返し表示されるステータスタグ（HP / CD / AT / cost など）、`unit_details.json` による拡張説明欄、そして**最速行動計算パネル**：突撃壁の x 座標と「兵玉コードが先」オプションを入力すると、そのユニットが突撃中に最速で攻撃できる x 座標の集合を計算します。
- 最速行動パネルは `cd >= 0 && shoot >= 0` かつ壁系以外のユニットにのみ表示されます。

### 6. リンク集

『激突要塞』関連のリソースをカテゴリ別に表示し、クリックするとブラウザで開きます：

- **原作公式** — 激突要塞！公式サイト
- **中国語コミュニティ** — 百度貼吧、激突驿站、萌娘百科、大会 QQ グループ
- **日本語コミュニティ** — Discord チャンネル、青茶の要塞研究所、wikiwiki、Seesaa 攻略 wiki、掲示板

## 陣形コード形式

### ファイル形式

`1P.txt` / `2P.txt` は 1 行につき 1 陣形です：

```
陣形名&コード
```

### エンコード

61 進数で、文字テーブルは以下の通りです：

```
0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ
```

つまり `0-9`、`a-z`、`A-Z` の計 61 文字です。

各ユニットはユニット id と x / y / 半径・角度で構成され、先頭のコアタイプに続く 5 文字がコアの座標を表します。HP 情報は `#` 区切りでコード末尾に付加できます。`Main.compileFort()` がコードを解析し、`to_xyr()` が座標をデコード、`Formation.encodeHp()` / `decodeHp()` が HP のエンコード・デコードを担当します。

### ファイルエンコーディング

入力ファイルは UTF-8 または GBK の可能性があり、BOM を自動検出して正しく読み込みます。出力は常に UTF-8 です。

## FAQ

**Q1：起動時に「formula.json が見つかりません」と表示される。**
リソースファイルが欠落しています。ソースから実行する場合は、`src/main/resources` のすべてのファイルが `target/classes` 以下に存在することを確認してください（`build_exe.bat` は自動的にコピーし、IntelliJ IDEA も通常は自動処理します）。

**Q2：シミュレーション結果がおかしい。**
陣形コードの形式（`名前&コード`）とユニット座標が正しいか確認してください。まずワークベンチの解析機能で検証することをおすすめします。

**Q3：エフェクトプラグインが反映されない。**
プラグイン JAR が `effects/` ディレクトリにあり、`Effect` インターフェースを実装して `ServiceLoader` で登録されているか確認してください。`effects/samples/CopyAndRenameEffect.java` を参照。ファイル名が `_` で始まるプラグインは無効化されています。

**Q4：テーマ切り替え後に一部の UI が更新されない。**
テーマ切り替え時はすべてのタブが更新されます。それでも異常がある場合はアプリを再起動してください。

**Q5：EXE はどうやってビルドする？**
プロジェクトルートの `build_exe.bat` を実行してください。出力は `dist/` に生成されます：

- `dist/激突Kit/激突Kit.exe` — アプリケーションイメージ
- `dist/激突Kit v1.8.0.zip` — リリース用アーカイブ

初回ビルドは JRE ランタイムの生成のため時間がかかりますが、以降は `dist/runtime_cache` を再利用して高速化されます。
